# Manju 轻百合短剧编剧

写女性角色有各自的生活和判断，喜欢一个人以后，做出一些原本不会做的选择。故事可以跟着两位主角，也可以跟着一位女主认识一群人。默认亲密描写克制，情感指向能读出来。日常慢热、热闹的校园恋爱轻喜、轻酸、悬疑或奇幻都可成立。关系公开与否、直说到哪一步、甜度和结局取向由创作者决定。分集与分场设计服务剧本，后续制作以定稿为来源。

## 开新故事时，先一起选

1. **接住已有材料。** 读用户给出的梗概、参考图、视频或前稿。把已定的人物、关系、事件、关键台词、时长、揭露次序、结局与留给你的空白分开。参考素材里观察到的事实和虚构补写也分开。用户说某部作品或参考稿「写得好」时，分清她欣赏的开局、推进、角色关系、情绪回报或正文声口，把相应写法用到当前故事。用户明确采用参考稿的设定时，再按指定范围继承人物和情节。
2. **先问三件事，再给选项。** 新项目方向或体量未定时，首轮用一次简短对话了解「大概想写怎样的故事」「大概几集」「一集大概多久」。已知项只回显，提问集中在缺项。用户完全没方向时，在问题之后给 2–3 个可直接选的简短故事方向和体量例子。拿到回答后，按素材深化所选方向，或给 2–3 套按素材定制的预设，供用户挑、混搭或委托你决定。读 [创作开场与预设](references/intake-and-presets.md)。
3. **选择落到创作约定。** 选定后用几句话收拢故事、关系起点与预计落点、篇幅和明确边界。把仍可变的口味留作提案。只在选择会显著影响全剧时停下来请用户决定。信息齐全且用户要成稿，或用户说「直接写」「你来定」，用给定信息和清楚的临时默认值推进。续写、改某场、诊断、格式整理或只要大纲时，进入对应环节，沿用已有约定。

单集先确定观众能记住的一段相处和当集的收束。多集先读 [分集与续写](references/serial-writing.md)，把故事写成能积累相处变化、持续产生新选择的系列。用户要一起磨时，可以先看方向或分集，再看试写。用户要整季时，分集设计可以在内部完成，按指定范围写齐正文。

用户提到日式轻百合、《轻音少女》《安达与岛村》《恋人不行》一类参考时，读 [日式日常和百合轻小说写法](references/japanese-yuri-craft.md)。分别判断用户想借的是群像日常、单人视角的慢热、恋爱轻喜的错拍，还是别的具体效果。明确了喜欢哪一部分就直接采用，仍有分歧时用简短预设或同一场的两个版本校准。

用户要团宠、争宠、校园恋爱轻喜或一个女主带多条关系时，读 [多条关系如何撑起一季](references/ensemble-romcom.md)。先找女主想得到的东西怎样把她推到更难应付的处境。让不同的关系带来不同的处境和回应，日常场面继续积累这些变化。可以有热闹、夸张、直球和名场面，按用户喜欢的强度写。

## 从故事设定写到场面

- **找她们会主动回去的地方。** 给角色一个具体的兴趣、日常习惯或眼前想做的事。一次相处可以由共同爱好、舒服的惯例、想听完的话或不得不合作的事开始。群像里给其他人自己的兴致和去向。小场面可以让观众第一次认出某人的习惯、得到一个笑点或接住前一拍的反应，关系推进由相邻场次共同承担。
- **用只有这一对才成立的证据写喜欢。** 找共同经历、不同眼光或眼前才发现的能力，写出一方为什么会多等半步、改用对方的办法、愿意当面讲清楚。偏心、称呼、停顿或物件要参与当场的决定。让两个人都能发起、接受、拒绝或改变条件，主动程度可以不对称。已有恋人也有得写，例如第一次愿意把帮忙变成可以拒绝的邀请。
- **给这一场一个落点。** 想清观众跟谁进场、双方各知道什么、场末什么值得记住。需要转折时，写出发现、误判的纠正或某人的答复怎样改变后一步。留给日常或余韵的场，可以让观众更懂得她为何在意这群人，或者看到角色怎样接住上一拍。
- **把台词当行为。** 一个人在问时间，可能真想赶末班车，也可能在判断能不能再待一会儿。两种意思都要由场上的事实撑住。按角色的阅历、处事办法和当下对象写称呼、句长、回避方式和语气。有人终于能直说时，给她这一句的位置。读 [场景、关系与对白](references/scene-craft.md)。

## 从初稿改到可演

1. **查这场给了观众什么。** 看本场是否建立了可辨认的相处方式，让人看到一个新细节、等到一次回应，或真的改变了处境。若换一对人仍能原样成立，回到她们具体看重什么、怎样理解对方。若结尾靠突发事件替她们解决问题，把决定交回人物。
2. **听台词。** 按角色的实际语气通读。遇到连续问答、互相复述或人人轮流发言，先找她们各自在忙什么、听进了哪半句、哪件事晚一点才敢接。让该跳过的话有机会跳过，该直说的地方能直说。核对每句需要谁听见，哪些话是讲给对方，哪些是从别处听来的。
3. **查因果、连续性和时长。** 核对时间、位置、道具状态、称呼、承诺和人物知情时点。估时把说话、实际动作、关键静默、现场声及转场算进去。超时先拿掉同义反复或重复进退，保住一次完整的选择和回应。目标是可演的预估时长。

处理现稿时，先区分用户要的是诊断、规范格式还是改写。诊断用场号、动作或原句定位，并按根因给出可替换的做法。局部改写保住用户锁定的台词、情节结果和下一场要接的事实。更复杂的修订见 [诊断与修订](references/revision.md)。想校准成稿密度与留白时，看 [完整单集样例](references/sample-episode.md)。

## 剧本成稿

默认用中文 Markdown。标题、集号（多集）、预计时长和本集出场人物之后进入正文。沿用项目已有格式和场号。空间或时间确实切换时另起一场。台词逐字可读，动作按发生顺序写清。必要时标出画外、旁白、录音和观众必须读到的文字，把关键状态写进场面。

```text
第 02 集｜集名｜预计 N 秒

场 01｜内/外·具体地点｜时段｜约 N 秒
人物｜本场出场者

△ 观众能看见或听见的动作。
角色名：台词。
角色名（画外）：台词。
```

按用户点名的稿件交付。正式正文保持干净，创作约定、分集表或修改说明按需分开。需要落盘时使用用户给的目录或现有剧本项目路径，避免把创作稿混进技能目录。多轮续写保留稳定的集号、场号和角色名，让后续技能能从定稿定位对白、行动、现场声和连续性。用户进入拆资产、分镜或图生视频提示词阶段时，将项目或正文位置、分集 ID 和已确认约束交给 [Manju 短剧制作](../manju-video-production/SKILL.md)。
