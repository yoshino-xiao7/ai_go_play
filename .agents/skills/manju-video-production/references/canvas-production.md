# 画布提交与制作留痕

## 开工与委派

读取目标项目、画布修订号、已通过镜号、角色固定版本和现有剪辑。沿用已有通过镜头的实际工作流与画风。以稳定镜号区分原片、定妆或关键帧、视频创作、制作说明和采用结果。跨镜复用时连接同一个固定版本，注明它在本镜的用途。保留旧版和失败候选。

给每个 Agent 分配镜号、责任卡片和需要登记的工作。需要统一写入时，由主 Agent 合并画布修订并代为提交。Agent 回报必须能定位其实际输入、操作、结果和质检，包含执行者、卡片 ID、固定版本、实际提示词或合成说明、任务／运行／渲染 ID、候选和采用结论。分析报告、脚本和临时预览属于工作证据。进入后续制作的参考或图层须作为素材卡登记，连接原始输入，并注明工具、参数和作者。

## 保存、提交、回读

1. 先在目标 Manju 画布保存创作卡的 `data.generation`。记录实际完整提示词、工作流、模型、质量、尺寸、输入模式、参数和参考顺序。每个参考从真实来源卡连线，边使用 `data.role: "reference"`，参考项使用 `source: "connection"`、`edge_id`、`node_id` 和固定 `version_id`。`reference_order` 以本次输入顺序保存。记录视频参考的用途、截取范围、是否取声以及定帧引导的版本和起始帧。合成、来源与成片之间的非输入关系线使用 `data.role: "relation"`。
2. 使用卡片上的生成按钮，或调用同一接口 `POST /api/generations`，传 `project_id`、真实 `source_node_id` 和已保存的实际配置，使用 `result_policy: "review"`。需要在画布自动编排中留运行记录时，先调用 `POST /api/projects/{id}/canvas-runs/plan`，再按通过的修订号提交 `POST /api/projects/{id}/canvas-runs`。选中下游会纳入可执行上游。需要复用既有图片时，使用固定素材参考卡并以关系线指回原生成卡，避免自动编排重新抽图。CLI 和无头流程也须先保存后提交。画布返回 409 时回读最新修订、合并本次变更后重试。
3. 用 `GET /api/generations/{job_id}` 或 `GET /api/canvas-runs/{run_id}` 回读任务和输出，再回读画布。核对实际模型、质量、提示词、输入顺序、固定版本与输出。记录实际用过的模型和任务。用户指定 GPT 2.6 精细创作时，使用 `builtin-openai-reference`、`builtin-openai-edit` 或 `builtin-openai-text_to_image` 中适合的入口，指定 `gpt-image-2.6-sunburst`、`quality: "xhigh"`。每次抽卡保留任务、候选及其对应的提示词和输入快照。修改同一卡片的草稿前，先保存上一轮真实记录。空卡首个结果可能自动显示，仍按候选处理。服务故障时保留原配置和真实状态，以可核对的任务为准。

## 合成、拼接与验收

- 制作说明分别记下实际采用的视频模型输出、图像模型原画、手工合成和时间线渲染。空的视频创作卡注明「未提交」，取消且无输出的卡注明「任务已取消」。沿用用户已确认的生成方式时，从实际成片回查采用的视频版本及对应的模型任务，方式有变更时在汇报里写明。
- 有生成内容时使用真实画布任务的输出或该任务输出衍生的可追溯图层。复用、纯图形或手工合成的镜头同样在画布留制作说明、实际素材版本、关系线和处理参数，按实际使用的方式记载。纯后期步骤记录编辑指令、实际输入和渲染记录。导入的预演只作为参考，实际成片从 Manju 对应的编辑和渲染入口提交。
- 在分镜或时间线绑定采用卡片与固定版本。时间线用 `source_node_id`、`asset_version_id`，分镜用 `video_node_id`、`video_version_id` 及对应音频字段。逐帧精确剪辑优先走时间线。保存修订后用 `POST /api/projects/{id}/timeline/render` 或 `POST /api/projects/{id}/production/render` 提交，随后回读 `GET /api/production/renders/{job_id}`。记录输出卡片、版本、帧率、精确入出点、音轨来源和渲染 ID。按原帧数剪辑，解码核对每个切点和音画同步。即使总帧数正确，也要核对切入首帧与源素材对应，逐帧排查黑帧、重复帧和缺失帧。需要更短片段或超出渲染上限时，按实际版本能力拆段并重新检查跨段切点。
- 逐帧检查当前候选，记录需返工的具体帧号和缺陷。对实际采用版本逐一做相邻切点核对，带声音按原速回看拼接，并逐帧核对切前、切后、动作接续、曝光、角色造型和边缘。亮度与清晰度统计可定位异常，仍须查看画面。记录所审视频版本、帧范围、拼接版本、发现的问题和处置。以上信息齐全且达到用户标准后才标记通过。
- 复刻原作动画时，在每镜同一列放原片和独立重制单镜，原片在上。两卡从同一镜内 F000 开始，正好覆盖相同的母版帧区间。共用逐帧对照时使用两卡真实的独立视频，标出镜内帧号和全片帧号。若实际采用素材来自多镜渲染，拆出该镜的精确帧段作为对照媒体，保留拼接渲染、剪辑入出点及对应连线；在浏览器里从两张卡实测首帧、中间帧和末帧。
- 逐帧与原作核对运动方向、动作相位、摄影机推进和横移、遮挡先后、定格与切换时机，也要检查角色发型、发饰、衣装、表情和手势。原作依靠角色转面、图形运动或遮罩切换时，分别登记对应角度原画、独立图形层和源帧时序。降维成静图的局部拉伸、边缘像素延拓、错相位淡入及人物软边重影判为返工。帧数、原曲同步和零掉帧只作为技术核对，画面与拼接分别记录验收。
- 如果擦掉底板里的原字来制作动画，按对应源帧登记字形、换句、进出时间、位置和人物遮挡，并把同一版的文字轨连到成片。逐镜查底部歌词、画内字和剪切首尾的单帧字效，也要检查四格或窗内复用是否引用了最新通过的对应画面。
- 原生拼接渲染后，将实际输出切点帧与对应单镜版本解码对照。如相邻片段在渲染时遗失首帧，可在底轨用实际采用版本首帧精确补位，保留抽帧来源、时间线和复验记录。补位后逐个复查切前、切入、切后帧及原声，继续检查本镜内的表演和造型。
- 一帧或数帧的补片需要回读实际渲染的前一帧、补片首尾与后一帧。若时间线短覆盖轨漏帧，可按原相位预合成完整独立单镜再从 Manju 画布提交，同时保留原独立补片、固定输入与连线。此镜换版后重新提交受影响的拼接并复查相邻切点，确认最终母版与验收用的单镜版本一致。

## 无头交付与项目导出

用 `GET /api/projects/{id}/export` 或对应项目导出命令取得可编辑的 `.manju`。同时交付视频、项目包和从实际任务回读的制作记录。原生项目包保留画布卡片、连线、草稿提示词、候选版本与素材，服务的生成、运行和渲染任务历史留在原库。导出前将必要的历史追溯写进对应镜头的画布卡片，包含执行者、原卡与任务标识、时间、实际提交提示词、编译后提示词（有差异时）、工作流／模型／质量、固定输入与输出、采用和拒绝结果、实际剪辑与验收结论。任务或运行详情可作为同批附件，只带制作需要的字段。素材使用画布的固定版本和连线，制作记录可同时保存素材哈希以便跨库核对。

使用画布界面可见的文字卡或原生历史面板展示历轮实际提示词，标出源创作卡、任务编号和结果。当前编辑器中的草稿、每轮提交原文和实际编译文本分别核对。旧任务引用的固定输入、定帧引导和候选输出也须通过画布素材卡或历史版本保入项目包，便于重新打开后查看原件。

导出后检查包内画布及引用的原件，逐条核对实际任务提示词、可见记录卡、连线、固定版本、候选、采用素材与剪辑记录。重新导入会重映射素材版本 ID，按保留的卡片 ID 和素材哈希核对。自定义工作流若未随项目包可用，另交付其定义并注明运行环境。无头模式也要能交付或重新打开这套可追溯记录。
