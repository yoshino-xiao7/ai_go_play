# Manju 短剧制作

接收编剧阶段的正文，把用户点名的集场拆成可实际组装的镜头。按正文保留角色身份、动作因果、信息揭示、精确对白与场次。场景地理、构图和运镜属于本阶段的设计，选定后写进分镜。发现涉及剧情取舍的歧义时，写明具体场次和选择。

## 实际制作必须从画布提交

- 用户要求继续创作、出图、生成镜头或重制时，先读 [画布提交与制作留痕](references/canvas-production.md)。使用目标项目的 Manju 画布作为制作记录。网页、CLI、API 和无头模式遵循同一流程。只要求剧本拆解、方案或提示词时，按要求交付文档。
- 每镜先建或更新创作卡，保存实际提示词、工作流、模型与参数，从真实来源卡连参考线并固定版本，再从这张卡提交任务。角色立绘、首尾帧、动作参考、修补遮罩和复用素材都要有可追溯的来源。用户指定 GPT 2.6 精细创作时，画布绘图使用 `gpt-image-2.6-sunburst` 及 `quality: "xhigh"`，并回读任务确认实际模型。
- 主 Agent 和子 Agent 的生成、抽卡、合成、剪辑及验收都要在画布留痕。委派时给出项目、镜号、负责的卡片与回报字段。每次提交回收执行者、卡片 ID、任务或运行 ID、输入和输出版本及审查结果。提交者也可以由主 Agent 统一代理，实际制作者和各自改动要记到对应卡片。
- 本地分析、逐帧对照和预演可作为参考输入。最终制作必须走画布创作、分镜或时间线对应的提交与渲染入口，保存合成参数、处理说明、实际采用版本和关联线。未满足画布记录和质量验收时保留为候选或待验收，继续修正。服务暂不可用时先保存可重试的画布草稿并记录阻塞。
- 每镜检查角色脸、发型、衣装、道具、动作和遮挡，逐帧定位闪黑、闪白、模糊色块、重复或丢帧等问题。用实际候选做前后镜拼接，按原速带音回看，并逐帧检查切点、运动方向、曝光、人物连续性和音画同步。发现问题记下帧号与原因，再重抽或修正。回读确认后才能标记通过。导出成片时同时交付可回读的画布及制作记录。

## 定位剧本和素材

- 用户提供 Manju 项目 ID 时，读取本机 `GET /api/projects/{id}/screenplay`，按 `document.episodes[].id` 和标题定位指定集，记录剧本 `revision`。若入口是剧本文件，就用确认过的正文及其集号、场号。现成正文可以直接制作。
- 用 `manju canvas inspect --project PROJECT_ID --json` 或项目 canvas API 读取主体卡、固定版本和画布修订号，必要时查看项目资产与原图。区分有素材的主体、独立图片、候选和文字备注。按实际内容匹配身份、造型和用途，再确认固定版本可读取。先复用符合设定的图。
- 读入当前剧集指定的画幅、视觉方向与目标模型。依据已有项目或附图提出缺省选择并注明。Manju 本地 MiniMax H3 读 [H3 图生视频与 Manju 交接](references/h3-i2v.md)。采用其他模型时，先核对其官方输入模式、时长、音频和镜头能力，采用对应提示词格式。

## 依次交付三份内容

1. **资产清单。** 逐场提取实际出现的人物、场景、道具及声音需求。给身份和可复用视图稳定编号。区分画布已复用、已有身份但需本集状态变体、待补素材、可随场景或首帧合成、后期添加。同一场地的反打和景别是视图，同一道具的完整与破损是状态。写出可见锚点、固定版本 ID 和使用场次。演员只在画外发声时，声音与形象需求分开判断。
2. **分镜。** 每镜写集内唯一 ID、正文来源场次、观众要读出的变化、成片与生成时长、首帧的动作起势、景别或运镜、切点及声音。保留观众能读到的空间关系。同一次接触只发生一次。对白、画外与心声分开排，声音可以跨镜，镜头长度按画面要交代的事定。
3. **图生视频提示词。** 给每段写明生成时长、引用版本和输入用途。待补的首帧记为 `KF-...` 或 `PLAN-...`。可复制的正文从首帧能接上的姿态开始，写表演的起因、动作过程、对方反应及切点。标清本次生成的原生声音与后期制作项。

交付前核对剧本场次、角色和关键道具的承载、分镜与首帧对应、原句及信息揭示顺序。试作时先挑一段能检验目标动作的戏，带前后切点看。用户反馈僵硬时，先查首帧有没有动作空间、实际输出的动作和剪辑是否可读，再按 H3 参考里的办法隔离提示词与工作流问题。

用户只要其中一项时，读取已有上游资料，交付指定项。用户指定整集试跑时，写齐这一集的三份文件。优先用用户给的目录或项目现有制作目录。在当前 Manju 仓库且未指定位置时，可用 `.manju/projects/<项目ID>/<分集ID>/` 下的 `资产清单.md`、`分镜.md`、`图生视频提示词.md`。这些文件供 Agent 和创作者交接，Manju 画布或分镜状态通过对应接口独立保存。后续改稿先对比新旧正文修订，只重做受影响的镜头。

用户要求实际制作时，接续目标项目已有资产、卡片和已通过镜头，按上述画布流程提交、复验和采用。用户指定整片或分段导出时，按同一画布版本导出成片和制作记录。

## 在 Manju 画布生成首帧

- 为 MiniMax H3 Image 写文生图、参考生图或编辑提示词时，读 [H3 Image 静帧提示词与画布接入](references/h3-image.md)，核对实际工作流里的素材顺序与提示词增强状态。
- 按 [画布提交与制作留痕](references/canvas-production.md) 建按镜号命名的创作卡，固定参考和旧版本。输入是本镜旧版时，用独立参考卡固定旧版并连到本镜。
- 群像先用全景或反打确认会影响剧情的路线、视线和人物位置。只为跨镜可辨或影响动作的邻座做固定参考。普通背景人物按画面需要处理。用户指定底图模型时，按任务记录核对实际模型。原立绘可单独用于身份参考。
- 使用 `result_policy: "review"` 保留候选。空卡的首个输出可能自动成为当前显示素材，仍须验收后才标记采用。生成完成后回读画布与任务，逐镜核对提示词、参考线、固定版本、当前采用图和上一版是否对应。

## 写法来源

- 视觉身份、状态变化与镜头瞬态分别管理。 [Drama Skills 资产拆解](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-assets/SKILL.md)
- 从原稿场次追溯镜头职责、冻结首帧与真实或计划挂图。 [Drama Skills 分镜](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-storyboard/SKILL.md)
- 提示词继承分镜的动作和图像证据，按目标模型约束写提交正文。 [Drama Skills 视频提示词](https://github.com/zenstory-ai/drama-skills/blob/main/skills/short-drama-video-prompts/SKILL.md)
