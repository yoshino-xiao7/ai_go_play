# 本机运维与恢复

## 运行边界

使用 start.cmd 启动，已有服务会复用。使用“退出程序”停止，有活动任务或保存失败时先处理提示。外部 ComfyUI 由原入口停止。开发和验收使用独立端口、配置与资料库，不删除用户草稿、不停止正在生成的任务或未知进程。

新安装默认用户目录 ManjuData，已有配置优先；实际路径以配置 root 为准。资料库包含 SQLite 元数据及对应媒体文件。项目 .manju 保存环境与下载缓存，.qa 保存本机开发证据，不进入源码。

日志位于 `%LOCALAPPDATA%\Manju\run` 和 `.manju\bootstrap\logs`。浏览器草稿用于恢复，不等于完整备份。

## 备份与升级

推荐空闲时正常退出，再复制整套资料库和对应配置到独立位置。不能只复制正在写入的 library.sqlite 而遗漏 WAL 和媒体；在线快照使用 SQLite backup API，并设计媒体一致性方案。

升级前保存备份、源码版本和配置路径。回退时保留失败现场，确认数据库与旧代码兼容，不以删除资料库解决启动问题。

工作台侧栏“关于”（或“设置 → 关于与检查更新”）可查看当前版本并手动检查 GitHub Releases。发现新版本后打开官方发布页阅读变更与安装说明，再执行上述备份和升级流程。检查不会自动下载或替换程序，也不会停止任务。无公开 Release、仓库私有或联网失败时，页面显示无法确认更新；这不影响本地创作。反馈问题前可复制运行信息，该摘要不包含本机路径、账号和作品。

如果更新了前端但原服务仍在运行，关于页会提示服务不支持新接口。等待任务完成后使用“退出程序”正常关闭本机服务，再运行 start.cmd；重复启动脚本会复用旧进程，不能替代重启。

## 故障定位

| 现象 | 检查 |
| --- | --- |
| 连接失败 / Not Found | 地址端口、health、前后端版本、启动日志 |
| 保存失败 | 保持页面打开；连通性、磁盘、浏览器存储和版本冲突 |
| 模型未找到 | 固定清单、导入目录、完整哈希、模型路径、组件重启 |
| 生成等待 | 队列、显存、节点日志、执行与回收状态 |
| 无法退出 | 未结束任务、安装、文件传输或画布保存 |

对外日志去除令牌、签名 URL、个人路径和素材信息，按 [支持指南](../SUPPORT.md) 报告。
