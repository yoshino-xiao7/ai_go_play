# 组件复用与迁移方案

本页是阶段 1 及以后的计划，尚未实施。原则与验证流程见 [Design System](README.md)，问题清单见 [样式债务](STYLE-DEBT.md)。

## 参照组件（保留视觉与交互特征）

以下组件在 2026-11-19 的实际渲染复核中表现良好。迁移时它们是规范的来源，不重新设计：

| 组件 | 保留的特征 | 作为参照的范围 |
| --- | --- | --- |
| 画布右键菜单 | 分组清楚、显示快捷键、危险项单独处理 | 所有菜单 |
| 提示词输入区 | 15px 阅读字号、一行控制栏、参考图位置 | 所有创作输入区（图像、视频、配音） |
| 视频参数弹层 | 分段选项、选中态、底部说明 | 所有参数弹层 |
| 剧本阅读排版 | 限制行宽、1.8 行高 | 长文本阅读区 |
| 项目卡片与卡片菜单 | 封面比例标记、菜单结构 | 所有资源网格 |
| 时间线轨道配色 | 按媒体类型区分颜色 | 媒体类型色（图、视频、音频、文字、主体） |

## 目标基础组件

每个基础组件统一 Token 与状态规则，不追求外观完全相同。

| 基础组件 | 现状 | 目标 |
| --- | --- | --- |
| Button | 19 套类名（`button`、`btn`、`canvas-small-button`、`screenplay-button`、`comfy-button`、`setup-*` 等） | 4 种变体（主、次、幽灵、危险）× 3 种尺寸（24 / 28 / 32px）；禁用态统一降为中性色 |
| IconButton | 至少 3 种尺寸体系，图标尺寸有 8 种（13–20px） | 界面中 16px 图标、画布工具栏中 20px 图标，描边统一 1.5 |
| Menu | `canvas-context-menu`、`canvas-more-options`、`dropdown`、`studio-select-popup`、`canvas-frame-options` 等 | 以右键菜单为参照 |
| Popover | 多处各自实现 | 以视频参数弹层为参照，使用 `--shadow-popover` |
| Tabs | 下划线、胶囊、分段 3 种样式，同一面板里混用 | 两种：页面分区用下划线，筛选用分段；同一区域只用一种 |
| Field | 输入框背景有多种冷色调写法 | 统一使用 `--color-surface-sunken` 与焦点 Token |
| StatusNotice | 黄色横幅、红色文字、琥珀色文字并存 | 成功、警告、危险、信息四种，使用语义色，并说明原因与下一步 |
| Dialog 表面 | `Modal` 与若干自定义遮罩（自动编排、查看器） | 统一表面、标题和关闭方式（工作区挂载方式另行规划） |

## 迁移顺序

先做影响面小、收益明显的项，每一步单独提交。

1. **状态色与禁用态**（D1、D2、D4）。接入 `--color-danger`、`--color-warning`、`--color-info`、`--color-focus`。这一步会产生可见变化，需要附前后截图。
2. **移除可见的旧色系**（D3）：按文件逐个处理，从 `comfy.css`、`subjects.css`、`canvas-runs.css` 开始。
3. **Menu 与 Popover 统一**（D9）。
4. **Button 与 IconButton**（D9）。先建立组件，再逐个页面替换，每次替换一个页面。组件已建立；项目首页试点已完成，见 [首页按钮记录](../../release/DESIGN-SYSTEM-PHASE1-HOME-BUTTONS.md)。其余页面尚未替换。
5. **字号与字重**（D5）。先处理时间线和画布状态栏。时间线与画布状态栏的试点已完成，见 [字号记录](../../release/DESIGN-SYSTEM-PHASE1-TYPOGRAPHY.md)。
6. **`canvas.css` 重复定义合并**（D7）。沿用阶段 0 的方法：分析每个属性的最终值，必要时加入窄视口与悬停状态做验证。
7. **层级排序修正**（D6）。这是可见变化，需要逐个验证弹层的叠放。
8. **遗留模板交互的去留**（D10）与面板动画（D11）。
9. **`@layer` 化**（D8）。在 `!important` 基本清理之后进行。

## 验证工具纳入仓库

阶段 0 的视觉回归工具依赖仓库外的黄金数据和测试项目。建议下一步：

- 在 `scripts/` 中加入测试数据生成脚本（合成素材、固定项目、剧本、时间线），使黄金数据可以复现；
- 加入回归采集与比较脚本，Playwright 作为可选的开发依赖，不进入运行时依赖；
- 在 [测试与验收](../TESTING.md) 中补充使用方法与判定标准。

这一步会新增开发依赖，需要单独评审。
