# Design System

ai-go-play 是以无限画布为核心的本地 AI 多模态创作工作站。本规范服务于这一定位：界面语言围绕**素材、节点关系、生成过程、候选对比、来源追溯和 Agent 协同**建立，保留暖墨中性色与玫瑰色的品牌气质。

本页说明设计原则、Token 的分层与使用规则、修改流程和验证方法。数值见 [Token 参考](TOKENS.md)，现状结构见 [级联审计](CASCADE-AUDIT.md)，待处理问题见 [样式债务](STYLE-DEBT.md)，组件复用计划见 [迁移方案](MIGRATION.md)。

## 适用范围

- `frontend/src` 下的全部样式与组件视觉。
- 不涵盖交互逻辑、数据模型、API 与工作区挂载方式；这些改动需要单独的技术设计。

## 设计原则

每条原则都对应可检查的标准，用来判断设计决定，而不是形容词。

1. **内容优先。** 媒体按原始画幅呈现，不额外留黑边；界面框架退后。1440×900 下打开一个侧面板时，画布内容区应不少于视口宽度的 60%。
2. **一种强调。** 玫瑰色只表达三件事：选中、主操作、「已采用」。其他控件使用中性色。
3. **状态说清楚。** 失败要给出原因和下一步。成功、警告、危险、信息使用独立的语义色，与品牌色的色相至少相差 30°。禁用的主按钮不得保持主按钮外观。
4. **可读的密度。** 中文文字不小于 12px，11px 只用于数字和英文元数据。层级依靠字号与 400 / 600 两档字重。Microsoft YaHei 没有 500 / 550 字重，无法靠它们区分层级。
5. **统一语言，不统一长相。** 右键菜单、提示词输入区、视频参数弹层、剧本阅读排版、项目卡片是经过实测的参照组件。组件之间统一 Token 与规则，保留各自的功能特征。

## Token 分层

| 层 | 命名 | 用途 | 谁可以引用 |
| --- | --- | --- | --- |
| 基础色阶 | `--ink-*`、`--rose-*` | 记录实际色值 | 只在 `tokens.css` 内部引用 |
| 语义 Token | `--color-*`、`--text-*`、`--space-*`、`--radius-*`、`--shadow-*`、`--z-*`、`--duration-*` | 表达用途 | 所有组件 |
| 历史别名 | `--bg`、`--panel`、`--accent`、`--canvas-*`、`--admin-*`、`--setup-*`、`--m-*` | 兼容现有规则，值来自语义 Token | 现有规则；新代码不再使用 |

`frontend/src/design/tokens.css` 只包含自定义属性，在 `main.tsx` 中最先导入，因此它在级联中的位置不会影响任何规则。

## 编写规则

- 新增样式不写十六进制颜色字面量，使用语义 Token。确实需要新的语义时，先在 `tokens.css` 增加 Token，并在 [Token 参考](TOKENS.md) 说明用途。
- 不新增 `!important`。现有的 `!important` 按 [迁移方案](MIGRATION.md) 逐个移除。
- `z-index` 不小于 40 的全局层级只能使用 `--z-*`；组件内部的局部层级可以继续使用小整数。
- 修改 Token 的值就是一次可见的设计变更：单独提交，附前后截图，说明理由。
- 标记为「建议」的 Token 尚未接入。首次接入时需要像普通视觉变更一样评审。

## 修改流程与验证

每个修改单元只处理一类样式或一个组件范围，完成后依次执行：

1. `npm --prefix frontend run build`（含 `tsc -b`）。
2. 相关测试：`node --test tests/governance.test.cjs`；涉及文档时执行 `python scripts/check_docs.py`。
3. 视觉回归。使用隔离端口、独立数据副本和固定测试项目，在 1920×1080 与 1440×900 下采集固定的界面状态，比较两项内容：
   - **计算样式指纹**：每个元素约 45 项计算样式及位置尺寸，必须完全一致；
   - **像素**：遮罩不稳定区域后，任一通道差异超过 24 计为变化。
   涉及 `max-width` 媒体查询时，追加窄视口（如 1200×800、840×700）；涉及悬停规则时，追加相应悬停状态。
4. 预期之外的变化先修复，再进入下一单元。预期之内的变化要在提交说明中解释，并附前后截图。

已知的环境噪声：设置页的磁盘剩余空间和资料库路径，在采集时遮罩。

阶段 0 使用的回归工具和黄金数据暂时保存在仓库外，方法与结果记录在 [阶段 0 记录](../../release/DESIGN-SYSTEM-PHASE0.md)。把工具做成仓库内可移植的形式，列在 [迁移方案](MIGRATION.md) 中。

## 失败与回退

每个单元单独提交。出现回归时，用 `git revert <提交>` 回退对应单元，不影响其他单元。不要用重写历史的方式回退已共享的分支。
