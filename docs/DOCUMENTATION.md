# 文档维护规范

长期手册应包含用途、范围、前置条件、操作、验证、失败恢复与关联入口，以读者任务组织。README 保留概要与导航，详细实现进入 docs，带日期的审计进入 release。

README 面向项目读者，介绍理念、功能、使用方法、贡献入口与社区。不要写 Agent 的工作汇报、重写过程、参考排版说明、验收数量或内部待办清单；执行记录与启用状态放在相应开发、发布文档中。

中文为完整维护版本，README_EN 同步项目入口；不声称尚未完成的全文翻译。上游许可、模型卡和 Agent 专项技能保留其内容与用途，不为统一文风修改授权原件或创作指令。

- 用具体行为描述能力，不写无依据的完美、精度或任意硬件承诺。
- 环境版本与包、锁文件、启动器一致。
- 区分实现、测试、未验证和计划；历史证据保留日期范围，不改成当前全面通过。
- 命令标明平台、目录和数据影响，使用隔离示例与占位路径。
- 使用相对链接，新文档加入文档中心，避免孤立与重复规范。
- 改治理时同步 PR 模板、工作流、规则集与测试。
- 不把文件已写好说成远程保护已生效，远程状态需要实际读取验证。

执行 `python scripts/check_docs.py` 和 `python scripts/check_release.py`。人工复核命令、外部来源、支持范围和状态，链接存在不代表内容或环境已验证。
