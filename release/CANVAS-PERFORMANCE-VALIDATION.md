# 大画布交互与草稿验证

验证日期：2026-11-14。测试使用一份 2391 个节点、6422 条连线、10,773,809 字节的画布快照。所有测试编辑和保存请求均被隔离，未修改原画布，未启动 GPU 生成任务。

## 原因与修复

- 拖动原先每次移动都同步序列化整张画布并写入 localStorage；大画布超出容量时草稿失败。改用 IndexedDB 存储结构化草稿，拖动和调整尺寸在结束时保存，普通编辑短暂合并后保存。
- 连线显示原先逐条扫描节点列表。改为按 ID 查找，保持未变化节点、连线的对象引用；后台生成结果合并也改用索引，并避开拖动期间。
- 平移原先触发整个画布编辑器更新。现在由 React Flow 更新视口，浮动编辑器在移动结束后更新位置。
- 撤销记录共享未修改的数据，避免每次拖动深拷贝整张画布。旧草稿只在新存储事务提交成功后迁移删除，其他窗口草稿及冲突备份保留。

## 实测

Windows Edge，无头浏览器、禁用 GPU，同一快照、1440 × 1000 视口，每次手势包含 24 个鼠标移动事件。下列数字是自动化手势的墙钟耗时，不是帧率保证；具体机器、可见媒体数和缩放比例会影响体验。

| 操作 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 平移 | 1.09 秒 | 0.39 秒 |
| 拖动卡片 | 12.97 秒 | 1.34 秒 |
| 拖动测试窗口内整图 JSON 序列化 | 28 次 | 1 次（服务端保存请求） |
| 拖动测试窗口内 localStorage 草稿写入 | 25 次 | 0 次 |

## 保存可靠性

已在真实浏览器通过：

- localStorage 填满后，12 MiB 草稿仍能写入并读取。
- 旧草稿迁移、新旧草稿时间比较、模拟配额失败保留旧草稿。
- 连续写入后删除无草稿复活，其他项目和会话草稿保留。
- 实际大画布离线拖动后保存草稿，全部节点内容和生成记录未变。
- 撤销 / 重做恢复准确位置，刷新后恢复离线草稿和同一保存请求编号。
- 草稿恢复对话框读取其他会话；重新连接模拟服务端后保存最新修改，只删除当前会话草稿。
- TypeScript 与 Vite 构建通过，无浏览器 JavaScript 错误。

可复查的本机隔离测试及结果位于 `.qa/canvas-performance/`。该目录含用户画布快照，不纳入开源发布。GPU 生成模式验收仍按用户要求等待现有创作任务完成。

## 旧页面如何更新

先确认画布保存成功。如仍有错误或冲突，先从右上角“更多 → 导出画布”下载 JSON 备份，再刷新页面加载新版。需要恢复时使用“更多 → 草稿恢复 / 导入 JSON”。不要清空浏览器站点数据；其中可能还有其他窗口未完成的草稿。新版仍会在有未保存编辑时提示离开确认，浏览器突然退出时不能保证最后一个尚未提交的写入完成。
