# 设计系统阶段 1：合并 canvas.css 的重复定义（2026-11-20）

本页是带日期的执行记录。方法见 [级联审计](../docs/design-system/CASCADE-AUDIT.md)「重复定义的处理」，问题见 [样式债务](../docs/design-system/STYLE-DEBT.md) D7。

## 范围

批准范围是迁移方案第 6 项（D7）：分批合并 `canvas.css` 中的重复定义，验收标准是可见行为不变。

- 只合并有证据证明可以删除或等价重排的部分。
- 不增加新的视觉样式；不修正层级；不引入 `@layer`；不改交互和其他页面；不进入第 7 项。
- 分支 `codex/design-system-phase0`，起点 `1fe982c`。只在本地提交，未推送，未合并。

## 方法

1. **枚举重复。** 解析 `canvas.css`，按「媒体查询上下文 + 完整选择器列表」分组，找到 31 组重复（全部在顶层），与阶段 0 的统计一致。
2. **逐属性记录。** 对每组的每条声明，按源顺序记录行号、值、`!important` 和特异性。同一组的选择器相同，特异性也相同，所以每个属性的胜负先看 `!important`，再看源顺序。
3. **判定被覆盖。** 如果更靠后、或优先级更高的同组声明设置了同一属性，或设置了能完整重置它的简写属性，这条声明对任何元素都不会生效。作为胜出方的 94 条声明都经 Edge 的 `CSS.supports` 确认能被解析。如果胜出声明在解析时被丢弃，前面的声明仍会生效，就不能删除。
4. **判定移动是否安全。** 合并时，仍生效的声明要移到另一个块，会越过两块之间的规则。只要中间有规则以完全相同的优先级（同为 `!important` 或同为普通，特异性相同）设置同一属性或相关的简写 / 子属性，就不移动。媒体查询内的规则同样计入。
5. **跨文件的关系不受影响。** 主题文件、React Flow 自带样式和其他组件样式在不同的样式表中，本文件内的调整不改变它们的相对顺序。

每组的结论（含所有阻碍规则）见交付目录中的《覆盖关系审计》。

- 冲突横幅和节点备注只在特定数据或情况下出现，用夹具注入真实类名验证计算样式，不是真实流程。
