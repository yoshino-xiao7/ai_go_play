## 范围与规则

- 只处理 `frontend/src/canvas.css`，不改其他样式文件，不做新的 `@layer` 迁移。
- 只删两类内容：

  - 在所有适用场景下都输掉的声明。
- 不能证明安全的标记一律保留，并写明原因。
- 分支 `codex/design-system-phase0`，起点 `b4004a1`；只在本地提交，未推送，未合并。

E 批删除的 4 条声明在任何情况下都会输：

- `studio-theme.css` 用 `html[data-theme="studio"] .canvas-comfy-button`（及其 `:hover`）设置了同样的属性；
- 那条规则同样带 `!important`，特异性更高，而且位于最先加载的入口 CSS；
- `data-theme="studio"` 固定写在 `index.html` 中，没有脚本会修改它。

### H 的原因

在“从画布选择”模式下，兼容的节点外层会加上 `.canvas-pick-compatible`。`studio-theme.css` 和 `review-experience.css` 通过 `.canvas-pick-compatible .canvas-node` 给这些节点加一圈描边（普通声明，特异性更高）。

- 原来，节点阴影上的 `!important` 压住了这圈描边，画面上显示的是节点阴影；
- 去掉标记后，描边显示出来，属于未经批准的视觉变化。

最终 HEAD 的第一次完整采集发现了这个问题：`canvas-pick-banner` 在 1440、1920 下各有 6 个节点的 `box-shadow` 改变。

漏检的原因：F、G 批的联合模拟只跑了一组精简的状态。这组状态是按“目标元素的名称”挑选的，而选取模式只在祖先元素上加一个类，元素名称不变，所以该状态没有被选中。

修正后的做法：

- 恢复这两个标记；
- 改用下面的全状态等价验证，覆盖所有画布状态；
- 作废那次完整采集，在修正后的 HEAD 上重新做一次。

## 方法

**逐条分析（`cascade_lib.js`）。** 在真实页面中，对每条 `!important` 声明可能匹配的每个元素，比较级联胜者：

- **场景：** 无交互、悬停（含只悬停祖先）、键盘焦点、焦点在内部、悬停加焦点、按下；表单控件另外翻转禁用状态。动态伪类用 data 属性模拟。
- **对比：** 每个展开后的子属性都计算两次胜者，一次带标记，一次去掉标记。
- **参与比较的声明：**
  - 已加载的全部样式表，包括第三方的 `vendor` 层；
  - 未加载的懒加载块源码，按加载顺序未知处理；
  - 元素的 inline style；
  - 正在运行的 CSS 动画。
- **简写与逻辑属性：** 展开成子属性比较；逻辑属性折算为物理属性。
- **媒体查询：** 只要可能与目标同时成立，就计入。
- **顺序判定：** 同一样式表内按源顺序；入口 CSS 一定在懒加载块之前；两个懒加载块之间顺序未知，特异性相同的情况视为可能改变。

**联合模拟（`cascade_sim.js`）。** 一批的所有改动一起应用，在每个元素、场景和宽度区间（每个媒体断点的两侧）上，比较改动前后“可能胜出的值”集合。

- 每个提交都先单独模拟“之前所有提交加本批”的累积状态，结果必须为 0 变化。
- 第一次联合模拟发现 18 处会改变胜者，后续两轮又因相互依赖剔除 7 处。这些都保留下来。

**全状态等价验证（最终 HEAD `386ed56`）。** 在当前代码上，模拟把 76 个已去掉的标记全部加回去，相当于回到起点的级联。然后比较两者在每个元素、场景和宽度区间上的胜出值。

- 范围：全部画布状态，1440、1920 两种视口，共 156 个探测，包括选取模式和懒加载顺序。
- 结果：1,846,932 次检查，0 处不同。
- 删除的 4 条 comfy 声明不在这个模拟中，它们由起点的逐条分析证明总是输：177 个探测，每个场景都被主题规则胜过。

**真实浏览器验证。**

- 每批：
  - TypeScript 检查与构建；
  - `node --test tests/governance.test.cjs` 14/14；
  - 受影响状态与相邻状态，在 1440×900、1920×1080 下逐元素比较计算样式和像素；
  - 涉及 640px 媒体查询的批次，在 640 与 641 两侧都采集。
- 每批计算样式的变化都是 0。
- 像素差异只出现在 640/641 的几张图中，全部位于未变化的 `<img>` 盒子内部。改动前的基线在同一代码上采集两次，也出现同样大小的差异，因此判定为图像栅格噪声。
- D 批另外用真实点击，采样了侧面板（D11）的打开与关闭动画。在默认动效和减少动效两种设置下：
  - `display` 的变化顺序、淡入淡出和关闭时机都与改动前一致；
  - 减少动效时同样立即切换。

## `@layer` 候选判断

本轮不实施新的分层。按上一轮实测的层叠规则：

- 分层的普通声明输给所有未分层规则；
- 分层的 `!important` 胜过所有未分层的 `!important`。

在此基础上，结论如下。

| 候选 | 判断 | 前置条件 / 需要的证据 |
| --- | --- | --- |
| 整个 `canvas.css` | 现在不能 | 它的普通规则目前靠特异性和源顺序胜过入口 CSS 中的基础样式（例如全局 `button` 规则）和主题。单独分层会全部输掉。需要先把 `styles.css` 的基础部分放进更早的层，并为主题确定层位置 |
| 只与本文件内部竞争的 12 处标记（102、108、142、620、621、836、850、853、1109、1119、1471、1561） | 条件成熟后可以随文件一起分层 | 层内的 `!important` 之间仍按特异性和源顺序比较，结果不变。前提是整个文件，包括 `.canvas-workspace button` 重置，放在同一层；并且用逐条分析确认它们不与其他文件中未分层的 `!important` 竞争（本轮数据没有发现） |
| 与 `studio-theme.css` 竞争的 12 处（1351、1352、1363、1371、1372、1377、1410、1411、1470、1477、1478、1502） | 不能 | 主题中针对这些元素的声明总是被覆盖，属于失效部分。需要先在主题中处理这些选择器，再重新做逐条分析，使这些标记先变成多余。另一种做法是让主题的层排在组件之前，但这会改变主题对其他组件的覆盖方式，需要对主题做完整审计 |
| 选取模式下的节点阴影（1474、1499） | 不能 | 它们要压住主题和 `review-experience.css` 中有意设置的选取描边。这条描边一直没有显示过。是否显示它属于设计决定，需要先确认，再处理这两个标记 |
| 1478 选中阴影 | 不能 | 分层后它会反过来胜过 `video.css` 中未分层的 `!important`，选中的视频节点外观会变化。前提是先处理 `video.css` 的这条规则，或让它和画布样式进入有序的层 |
| 1901 `.canvas-navigating` | 不受分层影响 | 它要胜过的是 inline 普通声明。分层的 `!important` 同样胜过 inline 普通声明 |
| 本轮已去掉标记的 76 条声明 | 不能单独分层 | 它们是普通声明，与整个文件受同样的限制 |

结论：`canvas.css` 目前没有可以单独、安全迁入 `@layer` 的规则。下一步按顺序：

1. 清理 `studio-theme.css` 中总是被画布覆盖的选择器；
2. 处理 `video.css` 中与画布选中态竞争的 `!important`；
3. 确认选取模式描边是否应该显示；
4. 确定基础、主题、组件三层的顺序，并为每一层重复本轮的逐条分析和全状态等价验证。
